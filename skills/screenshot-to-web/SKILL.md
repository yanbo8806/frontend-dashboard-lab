# 图片还原网页

目标是保留参考图的构图、信息层级、文字与关键形状，同时交付真实网页结构。工具负责测量和复核，代理负责理解图片与实现；这些脚本本身不调用模型生成网页。

## 开始前

先读项目规范，查看完整参考图、当前源码和最新实际渲染。旧报告、注释、“实测结论”都需要与图片核对。确认已有技术栈、参考尺寸、交互范围和允许使用位图的区域，沿用已明确的要求。只在缺少会改变交付形式的选择时提问，其余作合理假设并继续。

区分两类画布：固定运营大屏在原始宽高下实现，再整体缩放；普通网站使用流式布局，截图尺寸是验收视口，不是所有设备的固定画布。不要把这份示例的 1871×841 或三栏结构带到别的任务。

写一个简短的还原计划：主视觉与布局、需要保留的文本、静态素材/代码/交互的边界、最先修正的三个区域。照图还原时参考图优先，不因设计偏好擅自增加卡片、动效或重排内容。

## 看图和分层

先看全图，再放大标题、图表、重复组件和复杂素材。视觉识别决定“是什么”，探针验证“在哪里、多大、什么颜色”；两者不能互相替代。看不清的文本、估算数据和无原始素材的部分记录为不确定，不写成事实。

- 文字、按钮、导航、表格、KPI 和可交互图表优先用 DOM/CSS/SVG/现有图表库实现。
- 照片、纹理、复杂插画可以复用现有资源或经授权裁切。不要把整个面板、整页截图嵌入页面以刷相似度。
- 每个裁切检查是否已经含文字、徽标、飞线。先分离或清理，再放代码层；不能让同一文字出现两次，也不能用透明文本冒充可编辑。
- 字已烧入照片而原图缺失时，局部修补只能近似重建被挡住的景物。保留源图，记录衍生素材与损失；严格要求原景物时需要干净素材，不能声称无损。
- 图表先核对形状、坐标轴、图例、基线和颜色，再核对数据。参考图的角度、标注可能自相矛盾，记录矛盾并区分视觉示意与真实业务数据。

## 实现与迭代

1. 先对齐画布、区域边界和留白，再修字体大小/字距/字重/行高，最后补边框、光晕与装饰。优先处理结构错误、文字重影、图表形状错误；不要从 0.3px 阴影开始。
2. 复用项目栈，坐标或样式变量集中维护。DOM 坐标与舞台/面板/位图坐标只换算一次。SVG 的 viewBox 和实际墨迹盒要对应，渐变线优先使用 userSpaceOnUse。
3. 字体名看似存在不代表浏览器真的用了它。核对字体加载与回退；用局部截图比较候选样式，避免一味加描边把相邻字粘在一起。打包字体前确认许可。
4. 首次保存基线截图和报告到独立目录。构建成功后用固定视口截图，等待页面准备好和字体/图片加载。需要冻结的 Canvas 提供 window.__img2codeFreeze 钩子；固定截图与实时模式分别验证。
5. 每轮只聚焦少量相关区域。打开原图、渲染图和局部叠加图，结合区域差异找原因，然后修改。全局分数变好仍要检查重要局部有没有退步。
6. 使用项目既有阈值和素材划分。不能为通过而放宽阈值、扩大位图豁免、隐藏文字或跳过失败的检查。大幅修改评分器时，对基线与最终产物重跑同一评分版本。
7. 同时保留可运行代码、最新版截图、量化结果与残留清单；整体质量、可编辑性、交互和像素指标分别报告。mismatch 不是“还原准确率”，SSIM 也不是唯一视觉结论。

若连续数轮已无有效改进，记录真实瓶颈和已尝试方法，交付当前可审阅结果；不要承诺无条件像素级完成。需要新素材或扩大授权时停在相应边界。

## 本地工具

本 skill 随附 scripts/toolkit，Node.js 20+；PNG 工具使用 pngjs/pixelmatch，渲染使用 Playwright 与系统 Chrome/Edge。依赖就近安装，不能假设调用项目碰巧有同名模块。详见 [工具与命令](references/toolkit.md)，使用前阅读该文件。

已有可用工具时可以复用；没有浏览器或安装受限时仍可检查与修改源码，但必须明确截图与最终视觉效果未验证。工具不是自动生成器，不需要也不暗含外部 API 调用授权。

复杂偏差按需阅读 [诊断要点](references/diagnostics.md)。本次大屏的记录放在 [实证案例](references/dashboard-case.md)，其中坐标、形状与指标只适用于该参考图。

## 交付

给出源码、预览或最新截图、前后变化、验证命令及实测结果、剩余差异。只有执行过的检查才能说通过。不要用“构建通过”替代“视觉通过”，不要用地图位图的大面积一致掩盖文字和图表的差异。
